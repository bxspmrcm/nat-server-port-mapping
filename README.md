## NAT 服务器是怎么把内网服务放出去的

假设你机器在内网是 192.168.1.100，跑了 80 端口的 Web 服务，商家给你的公网入口是 200.10.10.1。外部用户访问 `200.10.10.1:80` 时，发生的是这么一轮往返：

1. 公网主机的报文目的 IP 是 200.10.10.1、目的端口 80，到达网关。
2. 网关查地址转换表，把目的 IP 换成 192.168.1.100，端口保持 80，转发给你机器。
3. 你的服务器响应，网关收到回程报文，按源 IP 192.168.1.100 和端口 80 再查一次表。
4. 网关把源地址换回 200.10.10.1:80，回给公网主机。

关键在于网关是**按服务逐个映射**的。部署 NAT 服务器，只是把服务器上某个特定服务向用户开放，并不是像静态 NAT 那样把整台机器的所有服务都摊到公网上。所以你在 NAT 机型上开放 25565 给 Minecraft，不等于别人也能从公网摸到你的 22 端口和面板端口。这是它比"直接给机器一个公网 IP"更收敛的地方。

商家侧用的多是 PAT（端口地址转换）：一个公网地址可以同时分配给多个内网地址共用，代价是必须同时转换 IP 和传输层端口。这决定了一件事，PAT 只支持 TCP、UDP 和 ICMP 查询报文，游戏和 Web 都没问题，需要协商动态端口的协议（比如主动模式的 FTP）就得靠额外的 ALG 处理。另一种 NO-PAT 模式下，一个外网地址同一时间只能给一个内网地址用，用户停了才释放，成本高，家用和低价 VPS 场景基本见不到。

现在再看"15 个端口转发"这个数字就清楚了：它限制的是你能对外暴露几个服务，跟速度没关系。Minecraft 一个 25565、泰拉瑞亚一个 7777、一个面板端口、一个语音端口，加起来还不到一半。

## 三种"NAT服务器"，先分清你搜的是哪一种

这个词在不同语境里指三样东西，混着看容易买错。

| 语境 | 具体指什么 | 典型场景 | 你是不是要买它 |
| --- | --- | --- | --- |
| 企业网里的 NAT 服务器 | 出口网关上配置地址转换，把内网服务器映射成公网地址的某个端口 | 只对外开放 Web、FTP 等指定服务 | 不用买，自己配或在防火墙上开 |
| 云厂商的 NAT 网关 | 公网 NAT 网关加 SNAT/DNAT 规则，让一批没有弹性 IP 的云主机共享出口或对外提供服务 | 多台云主机统一出口、统一入口 | 按需计费的网关实例，不是服务器 |
| 共享 IP 的 NAT VPS | 商家把一个公网 IP 切分，分给你若干端口 | 私服、小服务、单端口代理 | 本文讨论的就是这个 |

云厂商那套可以对照着理解：DNAT 规则对应"让外部访问你"，SNAT 规则对应"你主动访问外部"，购买 NAT 网关时还会自动往 VPC 默认路由表里加一条 0.0.0.0/0 指向网关，默认路由已存在就得手动补。这些是企业组网的活儿，跟你在雨云买一台 45 元的 NAT 机型不是一回事，别拿企业网关的规格去套 VPS。

## 常见问题

**NAT 服务器能建站吗？**
技术上可以映射 80/443，实际不建议。共享 IP 无法备案，国内机房对外提供 Web 服务属于违规风险；而且一台机器就 15 个端口，站点、面板、数据库管理端口很快就占满了。要正经建站，选独立 IP 机型。

**NAT 服务器和端口映射是一回事吗？**
端口映射是实现手段，NAT 服务器是部署形态。你在商家面板里加一条转发规则，背后做的就是端口映射，两者说的是同一件事的两面。

**映射配好了，外网为什么还是访问不了？**
按顺序排查：服务是否监听在 0.0.0.0 而不是 127.0.0.1；端口号是否落在商家分配的范围内；协议选的是 TCP 还是 UDP，选错就通不了；本机防火墙是否放行；部署在云上的还要确认路由确实指向了网关。这四步能解决绝大部分"配了没反应"。

**动态计费会不会比固定计费贵？**
高负载时段单价更高，账单是浮动的。负载稳定、常年有人在线，选固定计费更好预期；大部分时间空转的私服，动态计费通常更省。

**一台 NAT 机型能开几个服务？**
取决于端口配额，15 个端口以内随便分。带宽和 CPU 是另一回事，同时跑游戏服和转码这种吃满 CPU 的组合，动态计费会明显上去。
